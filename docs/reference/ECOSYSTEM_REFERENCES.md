# Sources and evidence register

Access/review baseline: 2026-11-24. Source IDs are used by the feature specs and traceability catalogs. Links are reference inputs, not imported source code or proof that planned behavior has passed. Public documentation was checked for the primary format/behavior anchors; candidate dependencies and oracle tools require pinned release/API/license qualification in implementation. Do not rely on mutable `main` or `latest` URLs in release evidence: record commit/release, digest and access date. Where original specification is incomplete, derive minimal independent test fixtures and track unresolved field semantics. This plan does not redistribute Apple's documentation or source code.

## Evidence to collect before promotion

For every binary profile keep a field/checksum ledger with byte offsets, value constraints, record count, units, version, source and independently generated test case; no unsupported assumptions about UDIF master checksum, zero/ignore behavior, LZMA framing, APFS feature flags or exact transactional commit sequence. Primary specifications describe formats but do not grant a patent license. Track source provenance and dependency notices. Research can cite publicly described behavior without translating implementation code. No professional legal clearance claimed. Licensing: proposed MIT OR Apache-2.0 for independently authored projects if confirmed by owners; respect existing repo license, review third-party terms/notice obligations and advanced APFS patent exposure. Refer to C8. Registry/package availability not assumed.
