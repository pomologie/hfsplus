# General-purpose HFS+ writes and Charles integration (H-MUT-01 through H-MUT-03, later)

Not a blocker for dmgez. Introduce `WritableVolume` only after read/check semantics are qualified; require explicit exclusive writable raw image/device adapter and source profile. No default physical disk access, no unsafe in-place changes on unrecognized volumes, no general-purpose write mode just because constructor exists. Keep mutable operations separate from immutable `SealedPlan`. `Transaction` stages create/remove/rename/move, write/truncate, allocate/free, symlink/hardlink, metadata/attr/fork edits and updates catalog threads, valence/counts, CNID allocator, extents overflow, allocation bitmap and B-tree splits/merges. Define locking/cache invalidation, ownership, free-space rollback, name collision rules, no cycles, atomic rename semantics and permission enforcement delegated to proper VFS. Handle ENOSPC, invalid handles and stale generation; failure leaves original state consistent. Initially mutation of disposable unjournaled image via explicit overlay/rebuild can serve dev tests, but do not expose it as crash-safe mounted write. Avoid treating an unsupported dirty volume as writable.

Journal transactions are separate milestone. Qualify Apple journal info block, header, endian/checksum, circular transaction block lists and wrap, block size and boundaries, replay idempotence and order. Document actual write ordering and persistence barriers: data dependencies durable before committed metadata, complete transaction log durable before home locations, checkpoint/advance log only after required durability. Use exclusive lock, read-only private replay when requested, actual writable replay only user-authorized with disposable test images first. Unknown journal flags unsupported. Handle interruption at every write/barrier, short writes, reordered/dropped writes, torn blocks within supported hardware fault model, log wrap/full, duplicate/replayed transaction, mount after failure. Do not promise atomic arbitrary multi-file data changes or hardware power-loss guarantees beyond documented device semantics. Fault-injecting block device records order and simulates failures; compare recovered state to last valid commit, fsck, native mount. Require a formal transaction invariants spec before implementation; fail release for any known corruption. Mutate existing Apple-generated clean/journaled fixtures, native tool read/write back and verify. Resizing later: plan grow/shrink, metadata relocation constraints, allocation checks, full preflight, no moving data without qualified transaction; refuse unsupported shrink safely. Verification remains read-only; physical disk repair/recovery not scope.

Charles integration: adapt core traits to kernel block device and VFS, no std/time/thread assumptions; choose allocator, scheduling/locking, error mapping, permissions, cache, flush barriers, page cache, memory pressure, concurrent operations, hot unplug and mount lifecycle in Charles. Kernel build, fault tests, sustained concurrency and mount/replay on disposable images required; no claim no_std alone suffices. Keep hardware/driver dependencies outside HFS+ library. Treat classic HFS wrappers, old macOS variants and compressed writes as independent profile extensions with evidence. Full mature filesystem release not prerequisite for dmgez 1.0.
