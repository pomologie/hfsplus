# HFS+/HFSX format, normalization and metadata (H-FMT-01 through H-FMT-04)

Primary baseline Apple TN1150 (S07), qualified additions by native fixtures on target OS. This specification is a design inventory, not a reproduced Apple specification. Maintain field ledger with evidence source, offsets, size, endian, range, profile, test IDs and writer default; unknown field is not license to zero an existing record. On-disk HFS+ fields generally big-endian; journal endian may be tagged separately. Distinct `ByteOffset`, `AllocationBlock`, `CNID`, `ForkKind`, `BTreeNodeId`. All arithmetic checked, reject malformed geometry and values outside device window. Initial volume header located at byte 1024, alternate near end according to validated volume geometry; reserved sectors allocated per spec. Verify signature/version, attributes, geometry, counters, next CNID, timestamps, Finder fields, clump sizes and five special-file forks. HFSX interpretation depends on actual key comparison policy, not signature alone. Check allocation-block count/size product, device boundaries and minimum geometry; unsupported wrappers/alternate layout explicit. Primary/alternate disagreement report, don't silently replace either. Raw detection separate from partition discovery (caller provides bounded volume).

## Special files and B-trees

Allocation bitmap tracks allocated/free blocks including reserved regions, metadata, payload and alternate header. Validate bit order, logical size and free count. Catalog, extents overflow, attributes, allocation and startup file forks represented by header descriptors. Special-file logical lengths and initial extents checked; bootstrap extents-overflow tree without circular lookup; qualify self-overflow rule. B-tree modules `node`, `header`, `map`, `key`, `search`, `bulk_build`, `verify`; no reuse of generic APFS tree. Parse header/map/index/leaf node kinds, node size from header with profile constraints, record count and reverse offset table, aligned/ordered offsets, key length and maximum, link range, tree depth, root, total/free nodes. Guard against cyclic links, duplicate node visits and invalid parent-child heights. Validate sorted record keys by actual tree comparator; index separator semantics match format (not generic B-tree assumption). Validate leaf chains in both directions and map allocation, root first/last leaves. Catalog contains parent CNID/name keys, folder/file/thread records with matching identities/parents and type fields, directory valence, folder/file counts, next CNID constraints. Names raw UTF-16 units, no lossy replacement for invalid sequences in inspection. Catalog lookup by normalized key; path display escaping distinct. Catalog thread record enables reverse lookup; consistency between entries and threads tested. Extents overflow keys include fork/file ID and starting allocation index; assemble ordered extents with no holes unless format-specific representation proves it, reject out-of-range/duplicate/shared ownership except valid hard link semantics; logical EOF <= allocated bytes. Attribute B-tree keyed by file/name/start block; inline/fork/overflow values, bounded xattr data, no fabricated data for unknown record. Support small and large xattrs and resource forks, FinderInfo and ACL metadata when representable. Avoid double-storing `com.apple.ResourceFork` or `com.apple.FinderInfo` in generic xattr set when mapped to special representation. Startup file read/recognize only in data-volume builder; boot semantics deferred.

## Names and identity

HFS+ uses historical Unicode decomposition and comparison rules (not modern NFD universally). Implement and verify canonical decomposition exclusions, historical collation tables/ignorable characters, combining sequence order, case folding and binary comparison rules for HFSX. Derive keys using documented permitted source data and differential fixtures. Test precomposed/decomposed pairs, supplementary UTF-16 pairs, combining marks/order, case variants, ignorable chars, historical exclusions, longest allowed name (255 UTF-16 units, not host character count), forbidden separators, NUL internal namespace, invalid sequences, slash/colon presentation conversion in host adapters; no lossy key. Normal user creation refuses internal reserved metadata names and illegal input; raw inspection can display escaped bytes. Resolve names and collision checks prior to allocation; collision error includes both source entries. Case-sensitive HFSX allows case-distinct names according to its actual comparator; normal HFS+ should reject colliding ones even if host permits. Stable IDs assigned by deterministic tree order, root and reserved CNIDs allocated according to format; ensure threads and alias IDs final, no collisions or wrap in builder, mutable writer later handles reuse/wrap. Volume name and root record consistency; validate maximum representable root name, not arbitrary ASCII-only restriction. Never conflate CNID with POSIX inode number for resolved hard links.

The core `NameFragment` API compiles host text under the admitted volume collation for matching against exact stored UTF-16 names. It bounds both the fragment and each candidate name. Callers handle directory enumeration and retain the matched raw names.

## Metadata model

Preserve POSIX owner/group/mode and BSD flags, file type and creator, 32-byte Finder user/extended info (validate exact sizes/flags), relevant directory/file flags, timestamps with format-specific epoch/precision and overflow checks, link identity, data/resource forks, xattrs (including large fork-backed attr), ACL representation where supported. HFS+ dates use unsigned 32-bit seconds from 1904 in baseline; maximum and preepoch dates must be explicitly rejected/normalized only by policy, never wrap. Distinguish unavailable metadata from zero. HFS+ name/metadata rules independently implemented; generated entries get explicit defaults. Regular file hard links: qualify native indirect-node/private directory representation, link reference allocation, link counts/metadata and hiding internal directories from normal traversal. Hard-linked directories and special cases separate reader profile; no cycles allowed in user tree. Builder supports ordinary regular file hard links before default claim, or explicitly fails strict requests until milestone is complete. Symlinks store target as data with correct catalog metadata; never resolve host target. Directory valence/thread and counts reflect actual on-disk objects including special private records where spec requires. Decmpfs compressed files are read-profile capabilities; don't accidentally interpret encoded resource fork as ordinary logical content. Logical and raw fork views distinct. Do not attempt compression on construction until semantics proven. No special device nodes default. All unknown flags/record variants handled as unsupported or preserved raw under explicit policy.

### H-FMT-01 volume header evidence

H-FMT-01-T01 passed on macOS 14.7.2 arm64 (23H311). `newfs_hfs` initialized 512 KiB, 8 MiB and 128 MiB partitionless, nonjournaled HFS+ images on temporary virtual devices. Smaller probes down to 8 KiB reported a 512 KB formatter minimum. Read-only `fsck_hfs` hfs-650.140.2 returned 0 for all three volumes. Each primary header matched its alternate byte for byte. The format test checked the native block size, count and alternate offset, then required typed errors for an invalid signature, truncated image bounds, and mutated allocation and fork geometry. H-FMT-01-T02 passed. `fsck_hfs` returned 0 after the alternate write count changed and 8 after removal of the final 512-byte sector from the 8 MiB raw image. On a separate native optical fixture, the reader reported the alternate difference and retained the primary.
