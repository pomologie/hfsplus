# HFS+ read-only engine, diagnostics and checking (H-READ-01 through H-READ-04)

Open immutable bounded device per C2. Read header and alternate in qualified geometry, validate signature/version/fields, decide HFS+ or HFSX comparator. If dirty/journaled state detected, read-only clean journaled volumes allowed only if validated empty/consistent; dirty journal profile default refuse logical view or report metadata-only `NeedsReplay`. Do not replay to source. Optional qualified replay into private overlay later; no promise latest data without replay. Unknown features/flags report and fail reads if they affect semantics. HFS wrapped volume support later: locate via independently verified wrapper fields, create bounded inner view, never ignore mismatch. Catalog/extents/attributes lazily open B-trees using bounded caches, avoid reading whole disk. Resolve `CNID`/root/path without host semantics, validate every lookup; search by exact format comparator and preserve raw name for display. Directory enumeration iterates key range, excludes internal metadata by default, exposes explicitly flagged raw records for inspector. Validate parent and thread IDs, directory valence and cycle limits. Hard links resolve regular link stubs to qualified private inode records, report missing link/reference as corrupt; directory links require separately qualified profile with cycle protection. Symlinks expose target bytes; optional resolution explicit within virtual root and bounded hops, no host I/O.

Fork reader maps logical offsets to initial/overflow extents, caps physical ranges, checks all allocations, data/rsrc independent; read exactly bounded slice. Attribute reader handles inline, fork and overflow records with length limits and correct typed mapping. Support `stat`, `list_attrs`, `open_attr`, `open_data`, `open_resource`, `read_link`, `extents`, paged `read_dir`, `inspect_internal`; unsupported raw record available only within budget. Logical content for compressed files: detect decmpfs attribute and flags, qualify individual compression type and stream framing (zlib inline/resource, LZVN/LZFSE later), sparse/hole behavior; cap expansion and validate logical sizes, never silently return empty file for unsupported encoding. Distinguish raw representation and decoded fork semantics; reading unrecognized compressed file returns Unsupported with path/type. Journal parser separate from general reader; no repair. Use bounded metadata/block cache, source identity and view ID. Iterator handles untrusted names, errors with byte location and path when safe. No unbounded recursion, allocation from unchecked counts, or processing of file contents during simple metadata inspect.

Journaled read admission requires a clean primary header last mounted by `HFSJ`, an initialized internal journal within the allocation area, and matching bounded cursors in a checksummed journal header. The journal and its info block must be disjoint from each other, the reserved header areas, and the fully embedded special file extents. Discovery reads only the two fixed journal prefixes and leaves pending or unsupported journals in the metadata-only profile. Public catalog operations omit the two root journal files, consistent with the macOS mount. Structural checks continue to account for their allocated fork blocks. The native fixture and provenance live in `crates/filesystem/hfsplus-reader/tests/fixtures/native-journal.json`.

For HFSX version 5, catalog comparison type `0xbc` selects binary UTF-16 ordering and `0xcf` selects the HFS+ case-folded comparator. Lookup and directory traversal use that comparator and retain the stored UTF-16 spelling in returned entries. Structural checks reject tree ordering that conflicts with the declared comparator. The nonjournaled case-folded fixture for H-READ-02-T01 passed Apple's read-only checker and native mount lookup on macOS 14.7.2 (23H311), arm64. [Apple TN1150](https://developer.apple.com/library/archive/technotes/tn/tn1150.html#HFSX) [Fixture provenance](../../crates/filesystem/hfsplus-reader/tests/fixtures/native-hfsx-case-folded.json)

`check` supports structural vs full. Structural validates headers, allocation geometry and tree ordering/maps/linkage, catalog thread/parent/valence/counters, extents ownership/range/overflow consistency, hard link references and attrs. Full verifies traversal and reading supported data/forks and allocation consistency; HFS+ does not give universal file data checksum, so distinguish structural validation from data authenticity. Verify special metadata files, primary/alternate state and free-block count, avoid marking valid if any required traversal unsupported. Report bounded issues, locations and counts; no writes, no repair mode. Native fsck is independent oracle; run on disposable images, never user disk. `hfsplus-cli inspect`, `ls`, `stat`, `cat`, `check`, `build` on raw volumes; raw internal node inspector options for educational/developer use; no recovery or file carving. Output JSON stable schema version. Tests cover native-generated clean, fragmented, large trees and forks, HFSX modes, hardlinks, symbolic links, Unicode, unknown fields/decmpfs type, dirty journal, malicious record counts, offset/extent overrun, cycle, truncated source. Ensure exact data and metadata via independent native oracle, lazy read counters, bounded errors.

`Volume::check_reachable_data` adds budgeted reads of stored data and resource forks and supported fork-backed attributes to the structural audit. It counts each resolved hard-link inode once and reports the owning fork and logical offset if a read fails. The report includes structural coverage gaps. Logical decompression and global orphan scans require separate checks. For H-READ-04-T01, tests use Apple-generated hard links and attribute extents to check exact payload budgets, a missing resource fork, and a read fault beyond the first block of a fork-backed attribute. [Hard-link fixtures](../../crates/filesystem/hfsplus-reader/tests/hard_links.rs) · [Attribute fixtures](../../crates/filesystem/hfsplus-reader/tests/attribute_forks.rs)

Stored forks opened through `RegularFile::open_stored_fork` own their extent mapping and borrow the volume. The caller can release the catalog and lookup record before streaming either fork. The H-READ-01-T01 regression reads both forks from a native hard link after those scoped objects have been released. [Stored fork lifetime regression](../../crates/filesystem/hfsplus-reader/tests/hard_links/fork_lifetime.rs)

`Catalog::symlink` admits a visible native symbolic link and reports its target size before reading the data fork. The target must fit both the caller's byte budget and the native profile. `Symlink::read` returns the exact nonempty, NUL-free stored bytes and never resolves the referent. [Catalog tests](../../crates/filesystem/hfsplus-reader/tests/catalog.rs)

`Catalog::macos_finder_info` projects FinderInfo for a public catalog ID using the effective metadata of a regular hard-link inode. It masks private catalog fields and the stored symbolic-link type and creator, reports an all-zero result as an absent attribute, and reports missing or inaccessible owners separately. Raw FinderInfo remains available in catalog metadata for image preservation. [Projection tests](../../crates/filesystem/hfsplus-reader/src/catalog/finder_info/tests.rs)

`Catalog::list_entry_attribute_names` includes distinct raw UTF-16 names from the visible entry and its validated hard-link inode. The listing applies a combined name limit. `Catalog::open_entry_attribute` reports ambiguous ownership when both entries store the requested name. The stored-owner operations on `Attributes` remain available for forensic reads. [Attribute ownership regression](../../crates/filesystem/hfsplus-reader/tests/decmpfs/entry_attributes.rs)

Preservation tools can check fixed reserved sectors with `Volume::reserved_sectors_are_clear` and require that their catalog belongs to the same volume view. `Volume::overflow_tree_is_empty` accounts for every allocated node of a tree that declares no records. `Attributes::visit_inline_attrs` checks the full allocated attribute tree before a caller can accept the inventory. It includes every recorded owner ID, including those absent from the catalog, and refuses fork-backed or unsupported records. H-READ-01-T01 and H-READ-04-T01 regressions cover native attribute framing, synthetic owner changes, malformed allocation coverage, and read budgets.
