# HFS+ read-only engine, diagnostics and checking (H-READ-01 through H-READ-04)

Open immutable bounded device per C2. Read header and alternate in qualified geometry, validate signature/version/fields, decide HFS+ or HFSX comparator. If dirty/journaled state detected, read-only clean journaled volumes allowed only if validated empty/consistent; dirty journal profile default refuse logical view or report metadata-only `NeedsReplay`. Do not replay to source. Optional qualified replay into private overlay later; no promise latest data without replay. Unknown features/flags report and fail reads if they affect semantics. HFS wrapped volume support later: locate via independently verified wrapper fields, create bounded inner view, never ignore mismatch. Catalog/extents/attributes lazily open B-trees using bounded caches, avoid reading whole disk. Resolve `CNID`/root/path without host semantics, validate every lookup; search by exact format comparator and preserve raw name for display. Directory enumeration iterates key range, excludes internal metadata by default, exposes explicitly flagged raw records for inspector. Validate parent and thread IDs, directory valence and cycle limits. Hard links resolve regular link stubs to qualified private inode records, report missing link/reference as corrupt; directory links require separately qualified profile with cycle protection. Symlinks expose target bytes; optional resolution explicit within virtual root and bounded hops, no host I/O.

Fork reader maps logical offsets to initial/overflow extents, caps physical ranges, checks all allocations, data/rsrc independent; read exactly bounded slice. Attribute reader handles inline, fork and overflow records with length limits and correct typed mapping. Support `stat`, `list_attrs`, `open_attr`, `open_data`, `open_resource`, `read_link`, `extents`, paged `read_dir`, `inspect_internal`; unsupported raw record available only within budget. Logical content for compressed files: detect decmpfs attribute and flags, qualify individual compression type and stream framing (zlib inline/resource, LZVN/LZFSE later), sparse/hole behavior; cap expansion and validate logical sizes, never silently return empty file for unsupported encoding. Distinguish raw representation and decoded fork semantics; reading unrecognized compressed file returns Unsupported with path/type. Journal parser separate from general reader; no repair. Use bounded metadata/block cache, source identity and view ID. Iterator handles untrusted names, errors with byte location and path when safe. No unbounded recursion, allocation from unchecked counts, or processing of file contents during simple metadata inspect.

`check` supports structural vs full. Structural validates headers, allocation geometry and tree ordering/maps/linkage, catalog thread/parent/valence/counters, extents ownership/range/overflow consistency, hard link references and attrs. Full verifies traversal and reading supported data/forks and allocation consistency; HFS+ does not give universal file data checksum, so distinguish structural validation from data authenticity. Verify special metadata files, primary/alternate state and free-block count, avoid marking valid if any required traversal unsupported. Report bounded issues, locations and counts; no writes, no repair mode. Native fsck is independent oracle; run on disposable images, never user disk. `hfsplus-cli inspect`, `ls`, `stat`, `cat`, `check`, `build` on raw volumes; raw internal node inspector options for educational/developer use; no recovery or file carving. Output JSON stable schema version. Tests cover native-generated clean, fragmented, large trees and forks, HFSX modes, hardlinks, symbolic links, Unicode, unknown fields/decmpfs type, dirty journal, malicious record counts, offset/extent overrun, cycle, truncated source. Ensure exact data and metadata via independent native oracle, lazy read counters, bounded errors.
