# hfsplus technology and dependencies

Rust edition 2024, resolver 3, pinned stable toolchain and validated MSRV, safe endian codecs from checked slices, mandatory `no_std + alloc` for core/format/reader/writer, core-only codecs where natural. `std` allowed in bulk builder, File/Read/Seek adapters, CLI, fixture collection and hosted concurrency; shared kernel logic stays no_std. EES-1 §3a defines target/feature gates. Explicitly audit `alloc` usage and any hidden standard-library dependency. `serde` optional for portable manifest/report adapters, `clap`/`indicatif` CLI only, `tempfile` for staging, `proptest`, `cargo-fuzz`, `cargo-nextest` (required), Criterion/Divan for benchmark harness. Use focused `flate2` or qualified pure Rust zlib for decmpfs reader, `lzfse_rust` or qualified LZVN/LZFSE decoder when supported, no compression in write-once builder initially. `crc32fast` not a universal HFS checksum; journal checksum is separately qualified according to format. Do not substitute Unicode normalization crate's modern normalization/case-fold tables for HFS+ historical rules; independently generate permitted table data from qualified historical Unicode and observed behavior, document exclusions and provenance. Inspect license of Unicode data and any derived tables. Host xattr capture belongs in caller/adapters; no host dependency in builder. No fstool or other HFS implementation runtime dependency. References: Apple TN1150, synthetic newfs_hfs/fsck_hfs fixtures, fstool, independent hfsplus crate (S05, S07, S11). Avoid copying GPL/APSL source or unlicensed tables. Use cargo-deny, audit and documented source policy. Release pin feature graph and no_std tests. No mandatory external tools for normal raw-volume operations.

## Verification integration

The [verification guide](VERIFICATION.md) and [obligation index](../../verification/obligations.json) define mandatory profile-specific verification gates in addition to the original acceptance tests. Apply [ecosystem standard EVS-1](ECOSYSTEM_VERIFICATION.md). No required proof, model check, native test or critical fault gate can be substituted by coverage or a self-generated round trip. `cargo-nextest`, property tests, fuzz/corpus replay, coverage and deterministic architecture checks are required; formal methods activate at the milestones in the obligation registry.
