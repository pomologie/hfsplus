# hfsplus qualification and engineering tests

Use actual synthetic native volumes generated by `newfs_hfs` (or diskutil) on licensed macOS; record command argv, OS build, geometry, input manifest and digest. Only redistribute fixtures populated with project-owned/synthetic data. Never embed proprietary Apple filesystem binaries or system disks. Independent reference readers fstool and hfsplus, qualify supported profiles and compare bytes/metadata, not internal algorithm. Native oracle read-only fsck on disposable detached raw image/device, attach read-only and collect metadata with native APIs/stat/lstat/readlink/xattr/forks; compare normalized names, modes, timestamps (precision), link equivalence and actual fork bytes. A reader parsing own builder is insufficient. Commands are qualified on OS runner first; never operate on actual host volumes or arbitrary device paths. Fail required oracle job if unavailable, skip explicitly elsewhere. Record `planned`, `pass`, `fail`, `unsupported`, `unavailable` status per fixture/profile/OS/version. Negative fixtures hand-mutated, truncated, overflow, malformed nodes, duplicate record, loop, range crossing, hardlink missing, dirty journal, unsupported decmpfs; no panics/hangs/unbounded allocations. Fuzz header, each tree/node/record, attr, extents, link resolver, compressed fork, journal once implemented. Proptest geometry, layout coverage, bitmap counters, normalized collision, stable IDs and packed node fit. Unit tests no_std compilation where promised, std adapters, exact I/O, source mutation and nonseekable sink. Large benchmark 100k files, multi-GiB data, metadata stress, random reads, owned memory/range spool. Raw builder deterministic with canonical manifest and fixed profile. Mutable tests later fault inject every persistent write/barrier, model old-or-new metadata consistency, native fsck and replay; no crash-safety claim before evidence. Release artifact independent of dmgez; integration test in dmgez using pinned release. See the [requirements](../reference/requirements.json) and [test catalog](../reference/test-catalog.json) for traceability. Planned tests are not executed by this pack.

## Verification integration

The [verification guide](VERIFICATION.md) and [obligation index](../../verification/obligations.json) define mandatory profile-specific verification gates in addition to the original acceptance tests. Apply [ecosystem standard EVS-1](ECOSYSTEM_VERIFICATION.md). No required proof, model check, native test or critical fault gate can be substituted by coverage or a self-generated round trip. `cargo-nextest`, property tests, fuzz/corpus replay, coverage and deterministic architecture checks are required; formal methods activate at the milestones in the obligation registry.

## Kernel portability acceptance (H-PORT-01)
Execute all applicable H-PORT-01-T01..T04 cases from first engine release. Build each affected crate independently with defaults disabled and explicit kernel features on aarch64-unknown-none and x86_64-unknown-none; check target dependency features; run host harness with and without std using identical fixtures; verify hosted-only dependencies cannot enter the kernel profile. Record exact command and result. See EES-1 §3a. Full builds required at release; Charles integration is separately tested.
