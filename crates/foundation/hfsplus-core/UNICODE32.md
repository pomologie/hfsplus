# HFS+ Unicode 3.2 decomposition

`hfsplus_core::names` implements the pinned canonical decomposition profile described in Apple TN1150 for macOS 10.3 and later. It produces bounded UTF-16 units, applies algorithmic Hangul decomposition, preserves the HFS+ exclusion ranges, and orders combining marks by Unicode 3.2 combining class. Equal classes retain their original order. Name admission, collision detection, and FastUnicodeCompare belong to separate layers.

The exclusions are U+2000–U+2FFF, U+F900–U+FAFF, and U+2F800–U+2FAFF. A scalar in one of those ranges retains its value. Combining classes still govern ordering. [Apple TN1150](https://developer.apple.com/library/archive/technotes/tn/tn1150.html#UnicodeSubtleties) · [Apple CoreServices encoding variants](https://developer.apple.com/documentation/coreservices/1399897-encoding_variants_for_unicode)

## Data provenance

The generator reads canonical decompositions and combining classes from CPython’s versioned `unicodedata.ucd_3_2_0` API. CPython builds that view from the Unicode Consortium’s 3.2.0 data. The checked-in table was generated by CPython 3.14.0 (`ebf955df7a8`). The generator copies datastore values and uses the HFS+ exclusions to select complete decomposition sequences. The table carries the [Unicode License v3](UNICODE-LICENSE). No CPython implementation or Apple case table is bundled. [Unicode 3.2.0 components](https://www.unicode.org/versions/components-3.2.0.html) · [CPython generator](https://github.com/python/cpython/blob/v3.14.0/Tools/unicode/makeunicodedata.py) · [Unicode terms of use](https://www.unicode.org/copyright.html)

Run these from the crate directory to check the checked-in bytes. Python is a development tool. The Rust implementation has no runtime Python or host Unicode dependency.

```sh
python3 tools/generate_unicode32.py --check
shasum -a 256 src/names/unicode32.rs
```

The SHA-256 for `unicode32.rs` is `76d7ed87e971178d1a0a6baf8df5054e33d997313e108b84f8b2286961d63c86`.

## Native evidence for H-FMT-03 and H-V03

The fixture in `tests/fixtures/native-normalization.tsv` records UTF-16 units independently extracted from the catalog of a synthetic APM HFS+ image on macOS 14.7.2 build 23H311, arm64. The capture tool uses `hdiutil makehybrid -hfs` on a newly created temporary directory of empty files. It reads the disposable image directly and requires no attachment. Regenerate to a temporary path before comparing with the checked-in result.

```sh
python3 tools/capture_native_names.py /tmp/hfsplus-native-normalization.tsv
cmp /tmp/hfsplus-native-normalization.tsv tests/fixtures/native-normalization.tsv
```

The fixture has 17 agreement cases for canonical decomposition, excluded characters, Hangul, supplementary scalars, and combining classes. Three probes expose newer Unicode behavior in the optical image tool. It assigns a combining class to U+1AB0 and decomposes U+1B06 and U+1109A, which Unicode 3.2 leaves unchanged. Tests preserve the pinned contract and the observed divergence. Native kernel-created volume comparisons and the historical case-folding qualification remain pending.
